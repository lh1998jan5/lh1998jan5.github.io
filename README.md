# friend-group-daily-reminder · V1.0

好友群每日提醒：一个不用安装、不用构建、可以离线打开的「假期倒计时」网页。打开后能看到今天、农历、星期、距离周末的天数，以及接下来几个节假日的倒计时；改好日期后可以一键复制成纯文本，直接粘贴到好友群。

页面已经适配手机 / 平板 / 电脑，整个目录可以直接推到 GitHub Pages，绑定自己的域名访问。

> **版本说明**：本目录是 V1.0。V2.0 的功能和配置与它完全相同，只调整了页面布局、背景呈现方式和绳子的定位（见文末「版本差异」）。两版是独立目录，改动不会自动同步，但可以共用同一份 `holidays.config.js` 和 `backgrounds/`。

## 页面布局与响应式

- 背景照片全屏铺满（`object-fit: cover`：按原比例裁切铺满，绝不拉伸变形）。
- 半透明毛玻璃卡片居中显示，日期、倒计时和按钮都在卡片里。
- 宽屏（>820px）一根绳子挂在视口顶部、卡片右缘与窗口右缘之间；使用 `position: fixed`（固定定位），页面滚动时绳子不跟着移动。
- 窄屏（≤820px）绳子收起，改成卡片右上角一颗 36px 的磨砂小圆钮，点击换一张背景（图标转半圈）。
- 布局全部是流式的（flex + 百分比 + `clamp()`），没有写死像素宽度，从 320px 手机到 4K 显示器共用一套代码。

主要断点：

| 视口宽度 | 大致对应的设备 | 变化 |
| --- | --- | --- |
| ≤ 360px | 小屏手机（iPhone SE 一代等） | 页面边距收到 12px，字号和按钮再收一档 |
| ≤ 560px | 手机 | 卡片内边距、圆角收紧，背景满屏 |
| ≤ 640px | 手机 | 「假期设置」改成从底部升起的抽屉，底部按钮两列 |
| ≤ 720px | 竖屏手机 / 小平板 | 编辑行由五列改三行：名称 + 右上角删除、日期 + 天数（带「天」）并排、说明一行 |
| ≤ 820px | 手机 / 竖屏平板 | 灯绳收起（贴着卡片边缘太局促），卡片右上角出现换背景小圆钮；768px 起卡片加宽到 680px |
| 821–1024px | 平板 | 灯绳照常，卡片 680px、圆角放大 |
| ≥ 1025px | 电脑 | 卡片 660px 居中，两侧留白 |

（表格是叠加生效的：例如 390px 的手机同时命中前三行。）

除了宽度，还处理了这些情况：

- **高度自适应**：矮窗口（高 ≤880px）自动收紧纵向间距；横屏手机（高 ≤560px）再压一档并隐藏最下面的说明行。页面上下留白按 `vh` 算，1366×768 的笔记本可以一屏放下。
- **安全区**：用 `env(safe-area-inset-*)` 给刘海、灵动岛和底部小白条留位置，iPhone 上按钮不会被小白条压住。
- **触屏**：主要按钮的点击区域放大到 40–54px（关闭、删除、换一张等），输入框字号 16px（小于 16px 时 iOS 聚焦会把整页放大）。
- **弹窗滚动**：假期列表和「背景图片」放在同一层，由弹窗主体统一滚动（没有嵌套的小滚动条），可视高度就是整个弹窗正文；滚到底不会带着背后的页面一起滚。
- **动效**：系统开启「减少动态效果」时自动关掉动画和淡入。

## 功能一览

- 显示公历日期、农历日期（页面内联农历库实时换算）、星期。
- 显示「距离本周周末休息还有几天」；周六、周日显示 0 天。
- 按日期从近到远列出即将到来的倒计时，内置元旦、春节、清明、劳动节、端午、中秋、国庆，也可以加入自己的提醒。
- 列表默认显示 6 条（可在代码里调整），跨年继续往后排。
- 「复制通知」生成一段纯文本，格式见下文，可粘贴到微信、QQ 等好友群。
- 「假期设置」弹窗：修改每个节日的首日和天数、添加/删除自定义提醒、设置背景轮换。
- 背景图片按分钟/小时/天自动轮换，也可以固定一张；电脑上拉一下绳子、手机上点卡片右上角的小圆钮（或弹窗里的「换一张」）立即换。
- 页面跨天后会自动重算；从后台切回页面时也会检查一次。
- 纯前端、无依赖、无需联网（农历数据和脚本都在 `index.html` 里）。
- 手机 / 平板 / 电脑自适应；背景图按屏幕自动选尺寸档，手机首屏只下载 100–300KB。

## 目录结构

```text
friend-group-daily-reminder_V1.0/
├── index.html                 页面本体（HTML + CSS + JS + 农历库，全部内联）
├── holidays.config.js         用户配置：节日修正、自定义提醒、背景名单与轮换
├── favicon.svg                站点图标
├── .nojekyll                  告诉 GitHub Pages 不要跑 Jekyll（必须有）
├── backgrounds/               背景原图（当前 12 张 .JPG，2–6MB，用于保留原始画质）
│   ├── 1280/                  手机/平板用的 1280px 长边版本（约 85–290KB）
│   └── 2560/                  大屏用的 2560px 长边版本（约 280KB–1.1MB）
├── scripts/
│   ├── make-bg-variants.sh    重新生成 1280 / 2560 两档小图
│   └── check-site.mjs         上传前自检（缺图、大小写、体积、根路径……）
├── README.md
└── .gitignore
```

说明：

- 页面不是严格意义上的“单文件”：`index.html` 里的样式、脚本、农历库是内联的，但用户配置和照片分别放在 `holidays.config.js` 与 `backgrounds/`。
- 原来的 `backgrounds/manifest.js` 已经不存在，背景名单统一写在 `holidays.config.js` 的 `backgrounds` 字段里。
- 没有 `package.json`、构建脚本或第三方依赖，不需要 `npm install`；`scripts/` 里的两个脚本也只用系统自带工具（Node 18+ / sips 或 ImageMagick），不是运行页面的依赖。
- `.preview/` 只是本地预览截图，已写进 `.gitignore`，上传时不用带。

## 快速开始

1. 保持目录结构不变，把整个文件夹放在任意位置。
2. 用浏览器打开 `index.html`（双击，或拖进浏览器窗口）。
3. 页面会自动读取同目录的 `holidays.config.js` 和 `backgrounds/` 里的照片。
4. 需要改日期或加提醒时，点主卡片底部的「假期设置」。

推荐使用 Chrome 或 Edge：它们的「保存到文件」可以直接覆盖 `holidays.config.js`。浏览器不支持 File System Access API 时（常见于 Firefox、Safari），「保存到文件」会改为下载文件，需要手动替换；显示、复制和保存到本机浏览器不受影响。

打开页面不需要启动本地服务器，也不需要联网。若通过 `file://` 打开，弹窗底部会显示配置文件的目录，方便确认保存位置；通过 `http://` 打开时不显示该路径。

想在本地模拟线上环境（`http://` 而不是 `file://`，剪贴板、图片缓存等行为更接近真实），在项目目录里起一个静态服务器即可：

```bash
python3 -m http.server 8080
# 然后访问 http://127.0.0.1:8080/
```

## 部署到 GitHub Pages

这个工程是纯静态页面：没有构建、没有依赖、没有后端，**整个目录推到仓库就能直接预览**。仓库里已经做好了这些兼容处理：

- `index.html` 在根目录，GitHub Pages 默认就访问它。
- 所有资源（`holidays.config.js`、`backgrounds/`、`favicon.svg`）都用**相对路径**，仓库叫什么名字、用不用自定义域名都不影响。
- 自带 `.nojekyll`，GitHub Pages 不会跑 Jekyll，`backgrounds/1280/` 这类目录会原样发布。
- 文件名大小写和配置完全一致（GitHub 跑在 Linux 上，区分大小写）。
- 线上版本会自动把「保存到文件」改成「导出配置」，并提示修改只存在当前浏览器。

部署前可以先跑一遍自检：

```bash
node scripts/check-site.mjs
```

它会检查入口文件、`.nojekyll`、背景图是否齐全、有没有写死根路径、文件体积和大小写冲突，有问题会以非 0 退出。

### 方式一：网页上传（不用命令行）

1. 在 GitHub 新建仓库（Public），比如 `holiday-countdown`。
2. 进入仓库 → **Add file → Upload files**，把本目录的内容拖进去：`index.html`、`holidays.config.js`、`favicon.svg`、`.nojekyll`、`backgrounds/`（含 `1280/`、`2560/` 两个子目录）、`scripts/`、`README.md`。`.preview/` 不用传。
3. Commit。
4. 仓库 → **Settings → Pages** → Source 选 `Deploy from a branch`，Branch 选 `main` + `/ (root)`，Save。
5. 等 1–2 分钟，访问 `https://<用户名>.github.io/<仓库名>/`。

> 上传时注意两点：
> - 保留目录结构：`backgrounds/1280/xxx.JPG` 不能变成 `backgrounds/xxx.JPG`，否则手机端会退回原图（还能显示，只是慢）。
> - 网页上传有时候会忽略以点开头的文件。如果 `.nojekyll` 没上去，点 **Add file → Create new file**，文件名填 `.nojekyll`，内容留空，提交一次即可。

### 方式二：Git 推送（推荐，后续更新方便）

```bash
cd friend-group-daily-reminder_V1.0
git init
git add .
git commit -m "feat: 假期倒计时（响应式 + GitHub Pages）"
git branch -M main
git remote add origin git@github.com:<用户名>/<仓库名>.git
git push -u origin main
```

推送后在 **Settings → Pages** 里同样开启一次即可。以后改了 `holidays.config.js` 或换了照片，`git commit && git push`，1 分钟左右生效。

### 绑定自己的域名

1. 先让站点在 `https://<用户名>.github.io/<仓库名>/` 上跑通。
2. 仓库 → **Settings → Pages → Custom domain** 填 `holiday.example.com`，Save。GitHub 会在仓库里自动生成 `CNAME` 文件。
3. 到域名服务商加解析：
   - **子域名（推荐）**：加一条 `CNAME`，主机记录 `holiday`（或 `www`），值为 `<用户名>.github.io`。
   - **根域名**：加 `A` 记录指向 `185.199.108.153`、`185.199.109.153`、`185.199.110.153`、`185.199.111.153`；建议同时加 `AAAA`：`2606:50c0:8000::153`、`2606:50c0:8001::153`、`2606:50c0:8002::153`、`2606:50c0:8003::153`。
4. 等 DNS 生效（几分钟到几小时），回到 Pages 勾选 **Enforce HTTPS**。

绑定域名后不需要改代码（所有路径都是相对的）。注意仓库里的 `CNAME` 文件不要删，删了域名就失效。

### 更新与缓存

- GitHub Pages 的 HTML / JS 默认缓存约 10 分钟。改完配置看不到变化时，先强刷（`Cmd/Ctrl + Shift + R`），或者等一两分钟。
- 想立刻失效，可以给配置文件加版本号：`<script src="holidays.config.js?v=20261028"></script>`，改一次加一次。
- 换照片时建议用新文件名并同步改 `backgrounds` 名单，避免浏览器命中旧缓存；换完记得重新生成两档小图（见「背景图片」）。
- GitHub Pages 每小时最多发布 10 次，连续改动较多时合并成一次提交更稳妥。

## 页面怎么用

### 主页面

- **日期区**：公历日期、农历、星期。
- **周末倒计时**：按周六计算；周一到周五显示距离本周六的天数，周六和周日显示 0。
- **倒计时列表**：按日期升序排列，第一条高亮。每条显示节日名、日期、放假天数和剩余天数。
- **来源标签**：
  - 没有标签：来自 `index.html` 内置的官方安排（2024–2026）。
  - 「手动」：来自 `holidays.config.js` 的 `years`（或本机保存的修改）。
  - 「推算」：该年份不在内置表里，按 `RULES` 规则估算。
  - 「自定义」：自己添加的提醒。
- **提示行**：列表里出现「推算」项时，下方会提示哪些年份的安排尚未公布。
- 页面每 30 秒检查一次日期；跨天后自动重算。切回标签页时也会立即检查。

### 复制通知

点「复制通知」，会生成类似下面的纯文本：

```text
【假期倒计时】
2027年10月27日｜农历九月廿八｜星期三

距离周末休息还有：N天
距离元旦还有：N天
距离春节还有：N天
……
```

实际条目取决于当前日期、展示条数和配置。复制成功按钮会短暂显示「已复制 ✓」；浏览器不允许写剪贴板时会提示失败，可手动选中文本复制。

### 假期设置

入口是主卡片底部操作区的「假期设置」按钮（在「复制通知」右边），不是页面右上角。弹窗打开后：

- 顶部显示 `holidays.config.js` 是否加载成功、本机修改是否生效。
- 列表默认是**今天起一年内**的节日；所有自定义提醒都会列出来（即使日期在一年之外），方便修改或删除。
- **改假期**：修改内置节日的首日和天数。天数允许 1–30；右侧会实时显示「至 X月X日（周X）· 共 N 天」。
- **加提醒**：点「＋ 添加」，填写名称、日期、天数，勾选「每年」表示生日、纪念日这类每年重复的提醒。新提醒默认是 7 天后、1 天。
- **删提醒**：点行尾的 ×。
  - 内置节日会变成「已隐藏」并变灰，点 ↺ 可恢复（保存后仍然可以恢复）。
  - 自定义提醒删除后，点保存并重新打开弹窗就会消失。
- **背景轮换**：设置每 N 分钟/小时/天换一张，或选「固定一张」并指定图片；「换一张」立即换。
- 日期或天数不合法时，对应输入框会标红，底部提示具体原因，无法保存。

弹窗底部四个操作：

| 按钮 | 作用 | 是否修改文件 |
| --- | --- | --- |
| 保存修改 | 写入当前浏览器的 localStorage，刷新后仍然生效 | 否 |
| 保存到文件 | 打开保存框，选中项目里的 `holidays.config.js` 并覆盖 | 是（不支持时改为下载） |
| 恢复为文件内容 | 清除本机保存的修改，回到 `holidays.config.js` 的内容 | 否（只清本机） |
| 取消 | 关闭弹窗，不保存本次改动 | 否 |

关于「保存到文件」：

- Chrome / Edge 支持直接选择并覆盖项目里的 `holidays.config.js`；写入成功后页面还会在本机存一份，保证显示与文件一致。
- Firefox、Safari 等不支持文件选择器时，会下载一份新的 `holidays.config.js`，需要手动覆盖项目里的同名文件，再刷新页面。
- 页面没有权限自动改磁盘上的文件，这是浏览器的安全限制；必须由用户选择文件或下载。
- 在配置文件已成功加载的前提下，保存时会同时写入假期修正、隐藏项、自定义提醒、背景名单和背景轮换设置，不会只写入其中一部分。
- 如果弹窗顶部提示「未找到 holidays.config.js」，先不要用「保存到文件」覆盖项目文件：此时页面读不到原背景名单，写出的 `backgrounds` 会是空数组。请先把配置文件放回同目录并刷新，再保存。

## 背景图片

- 照片放在 `backgrounds/` 目录，文件名写进 `holidays.config.js` 的 `backgrounds` 数组。
- 文件名区分大小写，扩展名要一致（当前照片是 `.JPG`）。
- 数组里写 `DSC07531.JPG` 或 `backgrounds/DSC07531.JPG` 都可以，页面会统一处理前缀。
- 名单为空时，页面会尝试 `bg-1.jpg` … `bg-6.jpg`、`bg-1.png`、`bg-2.png` 这些默认文件名；仍然找不到就保留渐变底色。
- 图片加载失败会自动跳过并尝试下一张；名单是显式配置的，失败时还会弹提示。

### 不规则尺寸 / 不规则比例怎么处理

- 背景一律用 `<img>` + `object-fit: cover` 等比铺满：原图是 3:2、16:9、还是竖拍，分辨率是 2000px 还是 6000px，都**不会拉伸变形**；和屏幕比例不一致时裁掉边缘（这是 `cover` 的正常行为，不改变清晰度）。
- 页面按「视口宽度 × 设备像素比」自动挑尺寸档：手机/平板拿 `backgrounds/1280/`，大屏拿 `backgrounds/2560/`，还不够才用 `backgrounds/` 里的原图。所以手机首屏只需 100–300KB，不再是 2–6MB。
- 挑不到某一档（比如新加的照片还没生成小图）会自动退回原图，不会出现空白背景。
- 旋转屏幕、拉伸窗口、接外接显示器时会重新判断一次档位，需要的话自动换更高清的那张。

### 新增照片

```bash
# 1. 把照片放进 backgrounds/（保留原始文件）
# 2. 生成 1280 / 2560 两档小图（macOS 用自带 sips，其它系统用 ImageMagick）
bash scripts/make-bg-variants.sh
# 3. 把文件名写进 holidays.config.js 的 backgrounds
# 4. 上传前自检
node scripts/check-site.mjs
```

变体脚本会保持文件名不变（包括 `.JPG` 大写），只按长边等比缩放，原图不动。想换尺寸档位，改脚本里的 `SIZES`，同时改 `index.html` 里的 `BG_VARIANTS`。

背景轮换的规则：

- 「每 N 分钟/小时/天」的 N 允许 1–999。
- 轮换状态记在浏览器的另一个 localStorage 键里；未到间隔时间时刷新页面会沿用当前图片。
- 选「固定一张」时，页面显示指定图片；此时拉绳子或点「换一张」会把固定图改成新图并记在本机。
- 修改轮换方式或固定图片后，需要点「保存修改」或「保存到文件」才会生效；「换一张」是立即生效的。

换背景的三种入口（效果一样，都是「换一张」）：

- **电脑**：按住卡片右侧的灯绳往下拉，松手换一张；轻点一下（几乎没拉动）也算换一张；键盘聚焦后按回车也行。
- **手机 / 平板（≤820px）**：灯绳会贴着卡片边缘显得局促，所以窄屏自动换成卡片右上角的小圆钮，点一下换一张，图标会转半圈。
- **弹窗**：「假期设置 → 背景图片 → 换一张」。

## 配置文件 `holidays.config.js`

这个文件是普通 JavaScript，不是 JSON，所以可以写注释、末尾留逗号；只要最后把对象赋给 `window.HOLIDAY_CONFIG` 即可。文件与 `index.html` 放在同一目录，刷新页面生效。

所有字段都是可选的，只写需要改的部分：

```js
window.HOLIDAY_CONFIG = {
  years: {
    "2027": [
      { name: "元旦", start: "2027-01-01", days: 3 }
    ]
  },
  hidden: [],
  custom: [
    { id: "birthday", name: "小明生日", start: "2027-05-21", days: 1, yearly: true }
  ],
  backgrounds: ["DSC07531.JPG", "DSC09069.JPG"],
  background: { mode: "hour", every: 6, fixed: "backgrounds/DSC07531.JPG" }
};
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `years` | 对象 | 按年份修正/补充节日。键是四位年份，值是该年的 `{ name, start, days }` 数组。`name` 用内置七个节日名时会覆盖该年的内置官方表或推算结果；用其它名字则作为额外节日追加。`start` 为 `YYYY-MM-DD`，`days` 为 1–30（含首日）。 |
| `hidden` | 数组 | 要隐藏的节日名，例如 `["元旦"]`。对内置节日和 `years` 里追加的节日有效，不影响 `custom`。 |
| `custom` | 数组 | 自定义提醒。每项 `{ id, name, start, days, yearly }`；`yearly: true` 表示每年按 `start` 的月日重复。名称最多 12 个字，天数 1–30。 |
| `backgrounds` | 数组 | 背景图文件名列表；可带 `backgrounds/` 前缀。**只从这个文件读取，不参与本机配置覆盖。** |
| `background` | 对象 | 背景轮换：`mode` 为 `minute` / `hour` / `day` / `fixed`，`every` 为 1–999，`fixed` 为固定模式下的图片路径（应出现在 `backgrounds` 名单里）。 |
| `updatedAt` | 字符串 | 页面导出时自动写入的时间，读取时忽略，可不管。 |

当前仓库里的配置：

- `backgrounds` 有 12 张照片。
- `background` 是 `{ mode: "minute", every: 1 }`，即每 1 分钟换一张。
- `years` 里预置了 2027 年的部分日期。这些是**手动配置**，不是内置官方数据；读取时来源会标为「手动」。未列出的节日（例如 2027 年国庆）在配置层仍按规则推算。

> ⚠️ 数据提示：`years` 里的 2027 年日期是本地手填数据，不是官方发布（国务院办公厅一般在前一年 11 月前后公布次年安排）。目前 `2027` 缺少国庆，页面会按 `RULES` 推算成 10 月 1 日起 7 天；其余日期也请按官方通知再核对一遍，不要直接当作正式数据。

## 数据来源与优先级

页面把「本机保存」和「配置文件」按**字段整体覆盖**，不是逐条合并：

1. 本机存过 `years`，就整个使用本机的 `years`，不再读文件的 `years`。
2. 本机存过 `hidden` / `custom` / `background`，同理整个使用本机的对应字段；没存过的字段才用文件里的。
3. `backgrounds` 例外：永远只读 `holidays.config.js`。

确定某一年某个节日的日期时，在生效的 `years` 范围内按下面顺序取：

1. 生效的 `years` 里该年有同名节日 → 使用它（页面标「手动」）。
2. 否则该年在 `index.html` 的内置官方表里（2024–2026）→ 使用官方安排。
3. 否则按 `RULES` 推算（页面标「推算」）。

`RULES` 的默认规则：

| 节日 | 规则 | 默认天数 |
| --- | --- | --- |
| 元旦 | 公历 1 月 1 日 | 3 |
| 春节 | 除夕（上一农历年十二月最后一天） | 8 |
| 清明 | 清明节气 | 3 |
| 劳动节 | 公历 5 月 1 日 | 5 |
| 端午 | 农历五月初五 | 3 |
| 中秋 | 农历八月十五 | 3 |
| 国庆 | 公历 10 月 1 日 | 7 |

推算只用于国家尚未公布安排的年份，天数是按近年惯例估的，不是官方数据。每年 11 月前后国务院办公厅公布次年安排后，在 `years` 里补上即可。

注意：保存到本机后，页面会把当时“文件 + 本机修改”的合并结果一起存下来。之后如果又直接编辑了 `holidays.config.js`，页面可能仍显示本机旧值；点「恢复为文件内容」可以回到文件内容。

## 修改代码

大部分自定义只需要改 `index.html` 顶部的两个注释区块：

| 位置 | 内容 |
| --- | --- |
| 注释 `① 基础配置` | `upcomingCount`（展示条数，默认 6）、`backgroundDir`（背景目录）、`backgroundProbe`（名单为空时的默认图片名）、`storageKey` |
| 注释 `② 法定节假日` | `OFFICIAL`（2024–2026 官方安排）、`RULES`（未收录年份的推算规则） |
| CSS `:root` | 配色（`--ink`、`--accent` 等）、圆角 `--radius`、字体 `--font` |
| CSS `.card` / `.bg-photo` / `.rope` / `.bg-switch` | 卡片宽度与透明度、背景铺法、绳子位置和长度、窄屏圆钮样式 |
| CSS `④ 响应式` | 手机 / 平板 / 电脑断点、安全区、触屏点击区域 |
| JS `BG_VARIANTS` | 背景尺寸档位（目录名和宽度），要和 `scripts/make-bg-variants.sh` 的 `SIZES` 对应 |

其余带编号的注释是内部逻辑，一般不需要动：

- `③ 工具`：日期、农历转换等工具函数。
- `④ 本地配置`：读写 localStorage、合并配置。
- `⑤ 节假日 + 自定义活动`：生成每年的节日和提醒。
- `⑥ 渲染`：渲染主页面。
- `⑦ 纯文本通知`：复制文本的格式。
- `⑧ 背景图`：轮换、按屏幕选尺寸档、预加载、交叉淡化。
- `⑨ 假期设置`：弹窗内的编辑逻辑。
- `⑩ 启动 + 跨天刷新`：启动和定时检查。

改 `index.html` 时注意：`OFFICIAL`、`RULES`、`ORDER`、`LABEL` 里的节日名要互相对应，否则列表里可能显示不出名称或覆盖不到。

## 备份与迁移

- 最稳妥的方式：把**整个文件夹**拷走（`index.html` + `holidays.config.js` + `backgrounds/`）。
- 至少也要带上 `index.html`、`holidays.config.js` 和 `backgrounds/`。
- 在本机弹窗里改过的内容只存在当前浏览器中，不会自动写进文件；迁移前先在弹窗里点「保存到文件」。
- 换浏览器、清除浏览器数据、移动文件夹位置，都可能导致本机保存的修改失效。

## 常见问题

**打开后提示「未找到 holidays.config.js」**

确认 `holidays.config.js` 与 `index.html` 在同一目录、文件名没有改。找不到时页面仍可使用，只是没有你的自定义配置，日期来自内置表和推算。

**改了配置文件，页面没变化**

先看弹窗顶部是否提示「本机修改生效中」。本机字段会整体覆盖文件字段；点「恢复为文件内容」可回到文件内容。也可以强制刷新（macOS 用 `Cmd + Shift + R`，Windows 用 `Ctrl + F5`）。

**「保存到文件」没有弹出文件选择器**

两种情况：

- 本地打开（`file://`）且浏览器不支持 File System Access API（Firefox、Safari 等）时，页面会下载一份 `holidays.config.js`。把它覆盖到项目目录后刷新页面即可。
- 线上打开（`https://`）时按钮会变成「导出配置」，只会下载文件——网页没有权限改仓库里的文件，必须覆盖并提交才会对其他人生效。

**上传到 GitHub Pages 后是 404 / 页面空白**

- 确认仓库根目录有 `index.html`，不是放在子目录里。
- 确认 **Settings → Pages** 已经开启，分支和目录（`/ (root)`）选对。
- 刚开启时要等 1–2 分钟，可以在仓库的 Actions / Pages 里看部署是否成功。
- Private 仓库在免费账号下不能开 Pages，需要公开仓库或付费方案。

**线上背景图不显示，本地却正常**

九成是大小写或目录层级问题：GitHub 跑在 Linux 上，`dsc07531.jpg` 和 `DSC07531.JPG` 是两个文件；另外 `backgrounds/1280/`、`backgrounds/2560/` 要跟原图一起上传。跑 `node scripts/check-site.mjs` 能直接列出缺了哪个。

**在线上改了假期，别人打开还是旧的**

线上改的只写进当前浏览器的 localStorage，只有你自己看得到。要让所有人看到：点「导出配置」下载 `holidays.config.js`，覆盖仓库里的同名文件并提交，等 1 分钟左右。

**手机上图片糊 / 加载慢**

糊：多半是 `backgrounds/1280/` 没传或传错位置，页面退回了原图以外的档位；慢：用的是原图。跑 `node scripts/check-site.mjs` 看变体是否齐全，也可以按需要调 `BG_VARIANTS` 的阈值。

**复制失败**

可能是浏览器剪贴板权限或页面上下文限制。先点一下页面再试，或手动选中通知文本复制。Chrome / Edge 直接打开本地文件通常可用。

**背景不变或一直显示渐变**

检查 `backgrounds` 名单里的文件名和大小写、照片是否真的在 `backgrounds/` 下；固定模式只会显示指定那张；轮换间隔没到也不会换。图片加载失败时页面会自动跳过。

**页面显示「推算」**

正常现象，表示该年份还没有内置官方安排。拿到国务院办公厅通知后，在 `years` 里补充日期即可。

**列表里的条数不够/太多**

改 `index.html` 的 `CONFIG.upcomingCount`（默认 6）。改完刷新页面。

## 已知限制

- 目前没有自动推送：不会发群消息，也没有群机器人、定时任务或邮件，只能打开页面后手动复制转发。
- 不会自动抓取国务院办公厅通知，官方安排需要自己更新到 `years`（内置表只到 2026 年）。
- 弹窗只能编辑「今天起一年内」的内置节日；更远年份和未被列出的节日要通过 `holidays.config.js` 配置。
- 网页不能自动写本地文件，保存配置只能通过文件选择器或下载。
- 仓库里同时保留了原图（43MB）和两档小图（约 9MB）。页面只会下载合适的一档，但仓库本身体积不小；如果要长期公开、只在意显示效果，可以删掉 `backgrounds/` 里的原图（先确认两档小图够用），仓库能压到 10MB 以内。
- GitHub Pages 每小时最多发布 10 次，频繁改配置时合并提交更稳妥。
- 自带的 2027 年数据是手动示例，需自行核对（见上文「数据提示」）。
